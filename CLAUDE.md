# Харви - как вести проект

Локальная голосовая помощница для Windows 11. Слушает микрофон, узнаёт имя «Харви», распознаёт речь
(faster-whisper), выполняет команды и отвечает голосом (Silero / Piper). Всё работает на этом компьютере;
для непонятых фраз используется локальная Ollama (`gemma4:e4b`). Язык проекта - русский: комментарии,
docstring, сообщения коммитов и ответы пользователю пишутся по-русски.

> **Обязательные правила - выполняются всегда, без напоминаний:**
>
> 1. **После каждой законченной правки - коммит.** Прогнал `pytest`, все тесты зелёные - сразу `git add` +
>    `git commit`, не спрашивая разрешения. Работу не заканчивай с незакоммиченными изменениями
>    (проверь `git status`). Логи, заметки, токены Google, модели и образцы голоса не коммить.
> 2. **Реализовал что-то заметное - впиши это сюда, в CLAUDE.md, в том же коммите.** Новая возможность,
>    новый инструмент или модуль, другой способ работы чего-то существующего, новая настройка → обнови раздел
>    [«Что умеет Харви»](#что-умеет-харви): что сделано, какими фразами вызывается, какой инструмент и модуль,
>    и в 1-3 строках - как это работает и почему именно так. Новый файл - строка в «Где что лежит».
>    Грабли, на которые наступил (падение, гонка потоков, странность Windows), - в «Что уже ломалось».
>    Пока описание не обновлено, работа не закончена: следующий ИИ знает о проекте только то, что написано здесь.
> 3. **Каждая починка и каждая новая фраза - тест.** Фраза из лога → ожидаемый вызов (`PHRASE_CASES`),
>    баг в логике → тест, который на старом коде падает.

## Запуск и проверка

```bash
.venv/Scripts/python -m pytest -q          # все тесты, ~2 с; запускать после каждой правки
.venv/Scripts/python -m pyflakes harvey.py config.py phrases.py log_report.py core tests   # опечатки, лишние импорты
.venv/Scripts/python log_report.py         # отчёт по harvey.log: что ушло в ИИ, ошибки, задержки, регрессии
.venv/Scripts/python harvey.py             # сама Харви (или ярлык «Харви.lnk», автозапуск из трея)
```

- Python 3.11, окружение `.venv`. Работает только под Windows (ctypes, COM, WinRT).
- Тесты не трогают микрофон, модели и PowerShell: `tests/conftest.py` подменяет список приложений, библиотеку
  Steam и `tools.execute_tool`. Фикстура `run("фраза")` показывает, какой инструмент был бы вызван,
  или `None`, если фраза ушла бы в ИИ.
- pyflakes ругается только на намеренное: реэкспорт pycaw в `core/util.py` и `import harvey` в `conftest.py`.
- Харви запускается в одном экземпляре (mutex), поэтому второй процесс сразу выходит. Изменения подхватываются
  после перезапуска: «Харви, перезапустись» или пункт трея «Перезапустить (применить изменения)».
  Сам Харви не перезапускай - она может быть занята (человек говорит, играет музыка): скажи, что нужен перезапуск.
- Если проверяешь вживую, не ставь на паузу и не закрывай то, чем пользуется человек (музыка, видео, окна).
  Чтение безопасно: `media.now_playing()`, `apps._top_windows()`, `browser.list_tabs()`. Запрос к Ollama для
  проверки - с `keep_alive=0` и только если не идёт игра (`grep "\[Игра\]" harvey.log`, `nvidia-smi`).

## Как идёт команда

```
микрофон (блоки 0.1 с) → громче порога? → record_utterance (до паузы; короткую команду - досрочно)
  → VAD → Whisper → stt.is_noise (галлюцинации, зацикливание) → имя: commands.split_address
  → сон / «стоп» / «да-нет» / «всё, спасибо» (harvey.py) → commands.handle_command:
       заметка, диктовка → выход → «замолчи» → «повтори» → «что ты сделала» → «ой, не то»
       → ответ на «Что открыть?» → parse.parse_all (правила, ~1 мс) → smart.parse (ИИ без инструментов)
       → Ollama с инструментами (один запрос) → tools.execute_tool
  → ответ: util.compose / compose_quiet → speech (очередь синтеза и воспроизведения, музыка приглушается)
```

## Где что лежит

## Что умеет Харви

Каталог возможностей. Формат: что - примеры фраз - инструмент (`FUNCTIONS`) и модуль - как работает.
Инструменты с пометкой «ИИ» есть ещё и в `TOOLS`: их может вызвать модель для фраз, которые правила не поняли.

### Слух, имя и диалог (`harvey.py`, `core/stt.py`, `core/commands.py`)

- **Постоянное слушание.** Блоки по 0.1 с; громче порога (калибруется при запуске) - начало фразы, пауза
  `SILENCE_DURATION` - конец. Перед Whisper - Silero VAD: стук, кашель и музыка не распознаются.
  Whisper `large-v3-turbo` на CUDA (не загрузился - `small` на процессоре), подсказки `WHISPER_PROMPT` и
  `WHISPER_HOTWORDS`. `stt.is_noise` отсеивает галлюцинации («Продолжение следует»), эхо подсказки и
  зацикливание («слава, слава, слава…»).
- **Имя.** Whisper ищет `WAKE_WORDS` (`util.find_name`). Имя после предлога - говорят о Харви, а не ей
  («в Харви добавить…»). Имя в конце фразы: команда перед ним («включи музыку, Харви»). «Эй, Харви» или одно
  имя - сигнал «слушаю», команда следующей фразой (`record_command`, `COMMAND_TIMEOUT`).
  Модель openWakeWord `wake/harvey.onnx` пока в режиме наблюдения (`WAKE_GATE = False`): решает Whisper,
  модель только пишет в лог, услышала ли имя; `log_report` считает, можно ли ей доверять. Образцы имени копятся
  в `wake/samples` (`WAKE_COLLECT`).
- **Досрочное выполнение.** После паузы `EARLY_SILENCE` короткая законченная команда («пауза», «громкость 30»)
  выполняется, не дожидаясь полной паузы (`parse.is_quick_command`); тот же звук второй раз не распознаётся.
- **Режим диалога.** `DIALOG_TIMEOUT` с после ответа можно говорить без имени, но только короткие команды,
  понятные без ИИ (`dialog_accepts`): разговор рядом не срабатывает. «Всё», «спасибо» закрывают окно.
- **Перебить.** «Стоп», «хватит», «замолчи» во время речи - без имени, речь обрывается сразу.
- **«Да/нет».** Опасное спрашивает подтверждение (`daily.ask_confirm` → `_pending`); время на ответ
  (`CONFIRM_TIMEOUT`) идёт с конца вопроса; «да, да», «да, удаляй» тоже подтверждают.
- **Сон.** «Харви, засни», «не слушай» (`sleep_mode`) - слушает только «Харви, проснись»; длинные фразы во сне
  не распознаются. Трей: «Спать» / «Проснуться».
- **Не отстаёт.** Звук старше `MAX_LAG_SEC` выбрасывается (в игре Whisper бывает медленным).
- **Служебное.** «Повтори» - последний ответ; «что ты сделала» - последнее действие; «ой, не то», «забей» -
  ничего не делать; «выход», «выключись» (только целой фразой) - Харви закрывается; «перезапустись» (`restart_self`).

### Разбор и ИИ (`core/parse.py`, `core/commands.py`, `core/llm.py`)

- **Правила без ИИ** (`parse_all`, ~1 мс): сценарии → календарь → вкладки и «назад» → сочетания клавиш → любые
  клавиши → файлы → кнопка на экране целиком → Яндекс Музыка → целые фразы (рядом, напоминание, устройство звука,
  громкость приложения, медиа, поиск) → калькулятор → таймер, дата, курс → разрезание по «и / потом / затем»:
  «открой телеграм и браузер» - глагол переносится, «закрой его» - подставляется последнее названное.
  `fix_hearing` заранее чинит ослышки (`HEARING_FIXES`).
- **Вопрос «Что открыть?»** на голое «открой» / «закрой» (не в браузере): ответ без имени - название.
- **Ollama с инструментами** - всё, что правила не поняли (тег лога «К ИИ»). Один запрос: `SYSTEM_PROMPT` с датой,
  история (`MEMORY_TURNS` реплик за `MEMORY_TTL` с) и `TOOLS`; текст озвучивается по предложениям прямо во время
  генерации; ответ после инструментов собирает код (`compose`), а не второй запрос. Подсказка с инструментами -
  около 5 тыс. токенов, поэтому `NUM_CTX = 8192`; в ней только дата без времени - так её кеширует Ollama.
  `execute_tool` отбрасывает выдуманные ИИ аргументы и подставляет похожие (`tab_index` → `index`).
- **Модель прогревается** при запуске (`_warmup_llm`, ждёт запуска Ollama до 3 мин) - не во время игры.

### Приложения и окна (`core/apps.py`, `core/winapi.py`)

- **Открыть** - «открой телеграм», «запусти obsidian», «телеграм» и точное название из Пуска без глагола -
  `open_app` (ИИ). Список из `Get-StartApps`, названия - `NAME_GROUPS`. Уже запущено - окно выводится вперёд.
  Нет такого приложения - сайт из `SITES` или игра Steam. Если приложение как раз закрывается («закрой телеграм и
  открой его»), ждёт конца процесса и запускает заново (`_wait_closed`).
- **Закрыть** - «закрой телеграм», «закрой браузер и яндекс музыку» - `close_app` (ИИ): WM_CLOSE, через
  `CLOSE_GRACE` - taskkill /F в фоне (кроме редакторов из `DOCUMENT_EXES`: там могут быть несохранённые файлы).
  «Закрой загрузки» - окно папки, «закрой ютуб» - вкладка. `PROTECTED_EXES` и сама Харви не закрываются.
  «Закрой это окно» - `close_active` (ИИ); «закрой все программы» - `request_close_all` → `close_all_apps` после «да».
- **Свернуть / развернуть** - «сверни стим» `minimize_app` (ИИ); «разверни браузер», «браузер на весь экран» -
  показать и развернуть; «сверни окно» / «на весь экран» - `window_state` (ИИ); «сверни все окна» -
  `show_desktop` (ИИ), «разверни все окна» - `restore_windows` (ИИ); «переключи окно» - `alt_tab`.
- **Раскладка** - «телеграм влево», «хром на второй монитор» - `arrange_window` (ИИ); «рядом хром и телеграм» -
  `side_by_side` (ИИ): не запущенное запускает и ждёт окно. «Окно влево / на другой монитор» - клавиши Win+стрелки.
- **Прочее** - «сделай скриншот» `screenshot` (Win+PrtSc, ИИ), «заблокируй компьютер» `lock_pc` (ИИ),
  яркость `set_brightness` / `change_brightness` (ИИ, «ярче», «яркость 50»).

### Браузер и сайты (`core/apps.py`, `core/browser.py`)

- **Сайты** - «открой ютуб», «гитхаб», «открой мою почту», «открой gemini» - `open_browser` (ИИ); список `SITES`
  в `config.py`, как их называют - `SITE_ALIASES`. **Поиск** - «ютуб котики», «найди рецепт борща», «загугли …»,
  «открой в браузере калькулятор матриц».
- **Вкладки через UI Automation** (фокус и клавиатура не нужны): «закрой вкладку / предыдущую / остальные /
  вкладку ютуб / вторую вкладку» - `close_tab` (ИИ); «перейди на вкладку гитхаб», «вкладка с youtube», «вторая
  вкладка» - `switch_tab` (ИИ, `name` или `index`); «какие вкладки открыты» `list_tabs` (ИИ); «скопируй ссылку» -
  `copy_link` (ИИ, адрес из адресной строки в буфер). UIA не видит вкладки - запасной путь клавишами.
- **Клавиши браузера** (`shortcut`): новая вкладка, следующая / предыдущая (после них голое «ещё», «назад» -
  тоже про вкладки 30 с), первая, последняя, вернуть закрытую, обновить, полный экран. Голые «назад» / «вперёд» -
  страница в браузере и проводнике, иначе трек; голое «закрой» в браузере - вкладка.

### Музыка и видео (`core/media.py`, `core/audio.py`, `core/uia.py`)

- **Плееры через SMTC** - «музыка стоп», «ютуб на паузу», «включи музыку», «следующий трек», «назад» - `media` (ИИ,
  `target` music / youtube / video). Видно каждый плеер отдельно, поэтому пауза ставится нужному и проверяется.
  Firefox иногда не принимает паузу - тогда медиа-клавиша. WinRT - только через `_smtc_run` (свой поток MTA).
- **Нечего включать** - открывается Яндекс Музыка (`MEDIA_FALLBACK_APP`) и кнопка «играть» жмётся через UI
  Automation (`_autoplay_when_ready`); «запусти яндекс музыку» - открыть и сразу включить (`play_app`).
- **«Что играет»** - `now_playing` (ИИ). **Лайк** - «поставь лайк», «убери лайк», «дизлайк» - `rate_track` (ИИ):
  кнопка «Нравится» в окне Яндекс Музыки; свёрнутое окно на полсекунды показывается поверх всех без активации.
- **Громкость приложений** - «музыку тише», «ютуб на 30», «громкость телеграма 50» - `app_volume` (ИИ).
- **Приглушение** - пока Харви говорит, фоновый звук тише (`Ducker`, `DUCK_FACTOR`); после сбоя громкость
  восстанавливается при запуске (`.duck_state.json`).

### Звук, микрофон (`core/audio.py`, `core/system.py`)

- «Громкость 30», «громче», «выключи звук» - `set_volume` / `change_volume` / `mute` (ИИ).
- «Переключи звук на наушники», «переключи звук» (по кругу), «куда идёт звук» - `audio_output` (ИИ) /
  `audio_output_info`; названия устройств - `AUDIO_DEVICES`; речь и сигналы Харви тоже переходят на новое устройство.
- «Выключи микрофон» - `microphone` (ИИ); включить обратно - голосом нельзя (Харви не слышит), только из трея.

### Клавиши и нажатия на экране (`core/system.py`, `core/uia.py`)

- **Сочетания** (`shortcut`, ИИ; список `SHORTCUT_KEYS`): копировать, вставить, вырезать, сохранить, выделить всё,
  очистить поле, Enter / Escape / Tab, прокрутка («пролистни вниз», «в начало»), вкладки, окна, «на уровень выше».
- **Любые клавиши** - «нажми ctrl g», «нажми alt f4», «нажми enter три раза», «нажми ctrl c потом ctrl v» -
  `press_keys` (ИИ). Названия клавиш голосом - `KEY_NAMES`. В окно самой Харви не нажимает.
- **Надпись на экране** - «нажми подписаться», «кликни на настройки» - `click` (ИИ): ищет кнопку, ссылку, пункт
  меню или текст в активном окне и его меню, нажимает через UIA (или мышью). Нет на экране - выполняет фразу как
  обычную команду («нажми следующий трек»); несколько похожих - просит уточнить.

### Файлы и папки (`core/files.py`, `core/apps.py`)

- **Папки** - «открой загрузки», «рабочий стол», «этот компьютер» - `open_folder` (ИИ, `FOLDERS`); «диск D» -
  `open_drive`; «открой то, что я недавно редактировал», «недавние файлы» - `open_recent` (ИИ).
- **В открытой папке проводника** (или «на рабочем столе», «в загрузках»): «создай питон файл main», «создай папку
  проекты» - `create_file` (ИИ, пустой docx/xlsx - из шаблона «Создать»); «открой файл отчёт» `open_file` (код -
  в редакторе, `TEXT_EDITOR`); «выдели файл отчёт» `select_file`; «выдели все файлы» `select_all`; «удали файл
  отчёт», «удали выделенное» - `delete_file` / `delete_selected` → «да» → `recycle` (только в корзину).
  Название ищется точно, потом похоже («мейн» ≈ main).
- «Закрой папку», «закрой папку загрузки», «закрой проводник» - `close_folder` (ИИ).

### Отмена (`core/undo.py`)

- «Отмени», «верни как было», «открой обратно», «верни громкость», «убери то, что вставила», «верни удалённый файл» -
  `undo` (ИИ). `execute_tool` перед действием запоминает, как было, после - кладёт обратное действие в стек
  (`UNDO_DEPTH`). Отменяются: громкость, яркость, закрытое приложение / окно / папка / вкладки, вставленный текст
  (Ctrl+Z в том окне), удалённое в корзину. Старше `UNDO_TTL` или нечего отменять - обычный Ctrl+Z.

### Время, дела, справки (`core/daily.py`, `core/calc.py`)

- «Который час», «какое число», «какой день недели» - `tell_time` / `tell_date` / `tell_weekday` / `tell_datefull`.
- «Таймер на 5 минут» - `set_timer` (ИИ), «отмени таймер» - `cancel_timers` (ИИ).
- «Напомни в 18:00 позвонить маме», «напомни через 20 минут…», «разбуди в 7» - `add_reminder` (для ИИ - `remind`
  со временем строкой); «какие напоминания», «отмени напоминания». Хранятся в `reminders.json`, пропущенные
  (ПК был выключен) звучат при запуске.
- **Заметки** - «запиши в заметки …», «заметка: …», «запомни …» - `add_note` (ИИ); «прочитай заметки», «открой
  заметки». Файл `notes.txt`.
- «Какая погода» - `weather` (ИИ, Open-Meteo, `WEATHER_CITY`); «курс доллара» - `currency_rate` (ИИ, open.er-api.com).
- **Калькулятор** - «2 плюс 2 умножить на 3», «15 процентов от 3200», «корень из 144», «5 миль в километрах»,
  «100 долларов в тенге» - `calculate`: числа словами, проценты, единицы (`UNITS`), валюты.
- «Загрузка процессора» `system_status` (ИИ), «температура видеокарты» `gpu_status` (ИИ, nvidia-smi).

### Google Календарь и Задачи (`core/gcal.py`)

- «Что у меня завтра» `calendar_agenda`, «когда следующая встреча» `calendar_next`, «добавь встречу завтра в 15
  на 2 часа красным» `calendar_add_event`, «удали встречу с врачом», «удали сегодняшнюю встречу» `calendar_delete`
  → «да» → `calendar_delete_id`; «добавь задачу сдать отчёт до пятницы» `task_add`, «мои задачи» `task_list`,
  «отметь задачу … выполненной» `task_done` (все - ИИ). День, время, длительность и цвет вынимает `parse._cal_when`,
  остаток - название. Вход в Google один раз (токен в `google_token.json`); без ключа - понятная ошибка.

### ИИ без инструментов (`core/smart.py`)

- **Вопросы** («что такое…», «почему…», «расскажи…», «как дела») - короткий ответ вслух; «кто такой / что такое X» -
  сначала выжимка из русской Википедии, нет статьи - модель.
- **Выделенный текст** (Ctrl+C): «объясни», «перескажи» - вслух; «переведи» на русский - вслух, на другой язык
  или «…и вставь» - вместо выделенного; «исправь ошибки», «перепиши вежливее / короче / по-деловому» - вместо
  выделенного. Ничего не выделено - берётся только что надиктованный текст или экран.
- **Экран** - «что тут написано», «что за ошибка на экране» - снимок активного окна уходит в модель (`VISION_ENABLED`).
- **Перевод вслух** - «как по-английски добрый вечер» - перевод читает голос этого языка (`SILERO_FOREIGN`).
- **Диктовка** - «запиши …», «напечатай …» - текст печатается в активное окно (`dictate`, вставкой или посимвольно);
  ИИ только расставляет знаки и заглавные, слова не меняет («запиши вежливо …» - переписывает стилем).

### Игры, сценарии, питание (`core/game.py`, `core/steam.py`, `core/parse.py`, `core/daily.py`)

- **Steam** - «запусти игру marvel rivals», «давай поиграем в риск оф рейн» - `launch_game` (ИИ): библиотека из
  appmanifest во всех папках Steam, названия сравниваются в латинице, запуск `steam://rungameid`.
- **Игровой режим** - сам при полноэкранной игре (`GAME_MODE_AUTO`) или «игровой режим» / трей - `game_mode` (ИИ):
  модель ИИ выгружается сразу после ответа (`GAME_KEEP_ALIVE`), приоритет Харви ниже, прогрева нет.
- **Сценарии** - «рабочий режим», «игровой вечер» (`SCENES` в `config.py`): шаги - обычные фразы, разбираются
  теми же правилами по очереди; непонятый шаг - ошибка, а не запрос к ИИ.
- **Питание ПК** - «выключи / перезагрузи компьютер», «переведи компьютер в сон» - `request_power` (ИИ) → «да» →
  `do_power` с задержкой `POWER_DELAY_SEC`; «отмени выключение» - `cancel_power` (ИИ).

### Голос и ответы (`core/speech.py`, `core/util.py`)

- Silero (`SILERO_SPEAKER`), не загрузился - Piper. Синтез в отдельном потоке заранее, пока звучит прошлая фраза;
  короткие фразы кешируются. Числа и латиница превращаются в слова (`normalize_for_tts`); куски без букв
  («🙂», «...») не синтезируются - на них Silero падал.
- **Интонации** `TTS_MOODS`: шутка - весело («расскажи анекдот»), таймеры и напоминания - чётко и громче,
  ночью (`NIGHT_HOURS`) - тихо.
- **Тихий режим** (`QUIET_MODE`): после обычного действия - только сигнал «готово»; вслух - время, погода, ошибки,
  вопросы. Род ответов - `FEMALE_VOICE`, обращение - `HONORIFIC` / `USE_HONORIFIC`.

### Трей, лог, отчёт (`core/tray.py`, `core/util.py`, `log_report.py`)

- **Трей**: цвет - слушает / говорит / спит; спать / проснуться, включить микрофон, игровой режим, заметки, лог,
  отчёт по логу, образцы имени, автозапуск с Windows (реестр Run), перезапуск, выход. Трей не трогает COM - только
  ставит флаги для главного цикла.
- **Лог** `harvey.log` (ротация `LOG_MAX_MB`): «Распознано», «Без ИИ», «К ИИ», «ИИ: текст», «Ответ ИИ», «Результат»,
  «Ошибка», «Время», «Wake» и др. `crash.log` - стеки падений в C-коде (faulthandler).
- **Отчёт** `log_report.py` (и пункт трея): что ушло в ИИ (✓ - теперь понимается правилами), что не получилось,
  ошибки в коде, регрессии, как слышит модель имени, задержки.

## Как добавить формулировку или команду

Основной цикл улучшений: открыть отчёт по логу, добавить фразу, написать тест, прогнать тесты, обновить
«Что умеет Харви», закоммитить.

1. `log_report.py` (или пункт трея «Отчёт: что Харви не поняла») показывает фразы, которые ушли в ИИ.
   Пометка ✓ значит, что текущие правила такую фразу уже понимают. Раздел «Регрессии» появляется, если правка
   что-то сломала. Разговор людей рядом («о, круто», «да, я иду, мама») в правила не добавляется.
2. Новая формулировка существующей команды - это строка в нужном списке `phrases.py`. Ослышка Whisper
   («диспетер», «полный кран») добавляется в `HEARING_FIXES`. Ещё одно имя приложения - в `NAME_GROUPS` в `config.py`,
   новый сайт - в `SITES` и `SITE_ALIASES`.
3. Новое действие:
   - функция в подходящем модуле `core/` (возвращает строку с префиксом, см. ниже);
   - запись в `FUNCTIONS` в `core/tools.py`, а если её должен уметь вызывать ИИ - ещё и описание в `TOOLS`
     (коротко: каждое описание занимает место в контексте модели, тест `test_tools_fit_into_model_context`);
   - правило в `core/parse.py`, которое возвращает `lambda: tools.execute_tool("имя", {...})`;
   - если действие можно отменить - обратное действие в `undo._revert_for`.
4. Добавь случай в `tests/test_phrases.py` (`PHRASE_CASES`): фраза и ожидаемые вызовы. Неудачи, которые уже
   были, тоже фиксируются тестами.
5. `pytest`, `pyflakes`, `log_report.py` без регрессий, строка в «Что умеет Харви», затем коммит.

**Порядок проверок в `parse_local` и `parse_all` важен.** Комментарии в коде объясняют, почему одно правило стоит
раньше другого. Примеры: «сними с паузы» не должно стать паузой, «включи звук» не должно стать медиа, «закрой
вкладку» - это `close_tab`, а не `close_app`, «вкладку назад» - клавиши, а не вкладка с названием «назад».
Регулярка, которая должна покрывать фразу целиком, пишется с `^…$`.

## Соглашения в коде

- **Ответ инструмента - строка с префиксом** (`core/util.py`):
  - без префикса - обычное действие («открыла Telegram»): в тихом режиме звучит только сигнал «готово»;
  - `INFO` (`~`) - это нужно произнести вслух (время, погода);
  - `FAIL` (`!`) - ошибка: сигнал ошибки и короткое объяснение;
  - `RAW` (`=`) - произнести ровно эту фразу (вопрос «Вы уверены?», «Что открыть?»).
- **Род.** Пиши `f"открыл{END}"`, а не «открыла»: `END` зависит от `FEMALE_VOICE`. Обращение «господин» в текстах
  пишется как есть, `util.address()` заменит или уберёт его по настройкам.
- **Импорты явные.** `from config import (...)` и `from phrases import (...)` перечисляют только нужные имена,
  `import *` не используется. Новая настройка добавляется в `config.py`, а затем в список импорта модуля.
  Неиспользуемых импортов и `# noqa` без причины нет - проверяет pyflakes.
- Действия выполняются только через `tools.execute_tool`: он пишет результат в лог, ловит исключения, подгоняет
  аргументы ИИ под функцию и запоминает, как было, для «отмени». Тесты подменяют именно его, поэтому в `parse.py`
  нужно вызывать `tools.execute_tool(...)` через модуль.
- **COM** (UI Automation, Shell.Application, WScript.Shell) - только через `winapi.com_call(fn, ...)` или обёртки над
  ним (`uia._with_com`, `browser._with_uia`, `files._with_shell`): объекты должны освободиться до `CoUninitialize`.
- Необязательные библиотеки (Google, piper) импортируются внутри функций: без них Харви работает, просто без этой
  возможности.
- Логируй через `log("Тег", текст)`. Теги «Без ИИ», «К ИИ», «ИИ: текст», «Результат», «Ошибка», «Время», «Wake»
  разбирает `log_report.py`. Не меняй их, не обновив отчёт.
- Стиль: короткие функции, docstring и комментарии по-русски, объясняющие «почему», а не пересказывающие код.
  Обычно в комментарии есть пример фразы из жизни и дата лога («закрой, браузер и яндекс музыку» - из лога 7 октября).
  Закомментированный код, TODO без плана и комментарии, повторяющие строку ниже, не оставляй.

## Потоки и Windows: что уже ломалось

- **WinRT и SMTC** (плееры) вызываются только через `media._smtc_run(...)`: он использует один поток MTA со своим
  циклом asyncio. Если вызывать `asyncio.run` из главного потока, где comtypes включил STA, каждый вызов даёт
  `RPC_E_WRONG_THREAD` (0x8001010e). Эти ошибки пишутся в `crash.log` как «Windows fatal exception».
- **COM-объект, отпущенный после `CoUninitialize`, роняет процесс** (access violation в `_ctypes`). Поэтому
  `winapi.com_call`: вызывает функцию, делает `gc.collect()` и только потом выходит из COM; у исключения убирает
  стек, иначе он держал бы объекты живыми.
- **Трей не обращается к COM** (микрофон, звук): из его потока процесс падал. Трей только выставляет флаг,
  а выполняет главный цикл (см. `system.mic_on_requested`).
- **sounddevice не потокобезопасен**: общий поток вывода открывает, ждёт и закрывает только `_play_worker`;
  `stop_speaking` лишь просит замолчать (`_interrupt`). `sd.stop()` из главного потока ронял Харви.
- `harvey.py` завершается через `os._exit(0)`: обычный выход при выгрузке CUDA падает с 0xc0000409. Перед этим
  `faulthandler.disable()`: иначе каждый выход дописывал в `crash.log` десятки строк стеков 0x80010108.
- `crash.log` - вывод faulthandler (стек при падении в C-коде). При запуске файл ротируется, если он больше `LOG_MAX_MB`.
- **Очередь микрофона не должна расти.** Пока игра на весь экран, Whisper на видеокарте распознавал фразу по ~20 с,
  звук копился, и Харви отставала на час: не слышала «проснись», а после пробуждения из трея «не отвечала».
  Теперь главный цикл выбрасывает звук старше `MAX_LAG_SEC`, во сне длинные фразы не распознаются
  (`stt.too_long_to_wake`), медленное распознавание пишется в лог (`[STT] распознавание заняло …`).
- **Контекст модели.** При `NUM_CTX = 2048` Ollama молча обрезала подсказку с инструментами (4.2 тыс. токенов)
  до 1 тыс., и ИИ видел четверть инструментов: «включи погромче музыку» вызывало `undo`, `switch_tab(tab_index=…)`.
  Добавляя инструменты, следи за размером (тест `test_tools_fit_into_model_context`). Разный `num_ctx` в запросах
  заставляет Ollama перезагружать модель - везде один `NUM_CTX` (кроме очень длинного выделенного текста).
- **Silero падает пустым `ValueError`** на тексте без букв и цифр («🙂», «...», «—»): `speech._SPEAKABLE_RE`.
- Яндекс Музыку Windows не видит как плеер, пока в ней ни разу не нажали «играть». Поэтому `_autoplay_when_ready`
  нажимает кнопку через UI Automation.
- Electron (Яндекс Музыка) отдаёт UI Automation кнопки страницы, только пока окно видно: свёрнутое или закрытое
  другими окно считается скрытым, и «поставь лайк» не находил «Нравится». `uia._shown` на полсекунды ставит окно
  «поверх всех» без активации (поднять наверх обычным способом Windows не даёт) и возвращает как было.
- Firefox отдаёт Windows один плеер на весь браузер и иногда не принимает паузу. В этом случае нажимается
  медиа-клавиша, но только если звучащий браузер и есть текущий плеер.
- **Закрытие доделывается в фоне** (Telegram и Discord на WM_CLOSE уходят в трей, их добивает taskkill через
  `CLOSE_GRACE`). Поэтому «закрой и открой» должно ждать конца процесса - `apps._wait_closed`.

## Подводные камни при правке файлов

- **Обратные слеши.** Регулярки в `phrases.py` полны `\b`, `\s`, `\1`. В этой среде Bash-heredoc и `python -c`
  могут превратить `\\b` в символ Backspace (0x08), и фраза молча перестанет работать. Тест
  `test_no_control_chars_in_source` это ловит. Правь такие строки инструментом Edit/Write, а не через shell.
- **Окончания строк смешанные**: одни файлы в CRLF, другие в LF (git хранит LF, `core.autocrlf=true`).
  `sed -i` в Git Bash молча переводит весь файл из CRLF в LF - дифф на весь файл. Правь инструментом Edit; если
  нужен скрипт - Python с `read_bytes` / `write_bytes`, сохраняя окончания файла. Проверка: `git diff --stat`
  не должен показывать изменение каждой строки.
- Имена в регулярках проверяются по тексту в нижнем регистре, без имени «Харви» и с исправленными ослышками
  (`parse.fix_hearing`).

## Как вести проект

Проект большой (≈14 тыс. строк, ~80 действий, ~400 фраз в тестах), поэтому:

- **Прежде чем править - прочитай.** Модуль целиком и его тесты; найди все места, где имя используется
  (`grep`): инструменты вызываются по строковому имени (`FUNCTIONS`, `TOOLS`, тесты, `undo._revert_for`),
  фразы - по ключу `R["..."]`, настройки - через списки импорта.
- **Начинай с лога.** Баги и непонятые фразы ищи в `log_report.py`, `harvey.log` (тег «Ошибка», «Результат: !»)
  и `crash.log` (смотри только записи после последних правок: старые стеки там остаются). Пример фразы и дата
  из лога идут в комментарий и в тест.
- **Одна тема - один коммит.** Чистку, починку и новую возможность по возможности не смешивай; сообщение коммита -
  по-русски: первая строка о том, что изменилось для пользователя, ниже - почему и как (с примерами из лога).
- **Не ломай поведение по умолчанию.** Новая настройка в `config.py` - со значением, при котором всё работает как
  раньше, и с комментарием, зачем она.
- **Большие файлы.** `parse.py` (~1300 строк) и `phrases.py` (~900) растут: новое правило - отдельная функция
  `parse_xxx`, вызванная в нужном месте `parse_local` / `parse_all`; большая новая тема - отдельный модуль в `core/`
  (как `browser.py`, `files.py`, `gcal.py`) со своей строкой в «Где что лежит» и своим разделом в «Что умеет Харви».
- **ИИ - запасной путь.** Всё частое должно разбираться правилами: ИИ медленнее (секунды против миллисекунд) и
  может ошибиться. Для ИИ - короткие описания в `TOOLS`, без новых правил в `SYSTEM_PROMPT` без нужды.
- **Безопасность действий.** Удаление - только в корзину и после «да»; выключение ПК, закрытие всех программ,
  удаление встречи - тоже после «да». Не закрывай `PROTECTED_EXES` и окна, из которых запущена Харви.
- **Зависимости** - в `requirements.txt`; необязательные импортируются внутри функций.
- **Документация.** CLAUDE.md - для ИИ (правила, устройство, каталог возможностей), README.md - для людей
  (что умеет, установка). Поменялось то, что видит пользователь, - обнови оба.
- **Пуш** (`git push origin main`) - когда попросит пользователь; коммиты - всегда сразу.
- Если что-то проверить вживую не удалось (например, пауза в браузере), прямо скажи об этом.
