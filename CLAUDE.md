# Харви - как вести проект

Локальная голосовая помощница для Windows 11. Слушает микрофон, узнаёт имя «Харви», распознаёт речь
(faster-whisper), выполняет команды и отвечает голосом (Silero / Piper). Всё работает на этом компьютере;
для непонятых фраз используется локальная Ollama (`gemma4:e4b`). Язык проекта - русский: комментарии,
docstring, сообщения коммитов и ответы пользователю пишутся по-русски.

> **Обязательно: после каждой законченной правки - коммит.** Прогнал `pytest`, все тесты зелёные - сразу
> `git add` + `git commit`, не спрашивая разрешения. Работу не заканчивай с незакоммиченными изменениями
> (проверь `git status`). Логи, заметки, модели и образцы голоса не коммить.

## Запуск и проверка

```bash
.venv/Scripts/python -m pytest -q          # все тесты, < 1 с; запускать после каждой правки
.venv/Scripts/python log_report.py         # отчёт по harvey.log: что ушло в ИИ, ошибки, задержки
.venv/Scripts/python harvey.py             # сама Харви (или ярлык «Харви.lnk», автозапуск из трея)
```

- Python 3.11, окружение `.venv`. Работает только под Windows (ctypes, COM, WinRT).
- Тесты не трогают микрофон, модели и PowerShell: `tests/conftest.py` подменяет список приложений
  и `tools.execute_tool`. Фикстура `run("фраза")` показывает, какой инструмент был бы вызван,
  или `None`, если фраза ушла бы в ИИ.
- Харви запускается в одном экземпляре (mutex), поэтому второй процесс сразу выходит. Изменения подхватываются
  после перезапуска: «Харви, перезапустись» или пункт трея «Перезапустить (применить изменения)».
- Если проверяешь вживую, не ставь на паузу и не закрывай то, чем пользуется человек (музыка, видео, окна).
  Чтение безопасно: например, `media.now_playing()` или `apps._top_windows()`.

## Где что лежит

| Файл | Что внутри |
|---|---|
| `harvey.py` | точка входа и главный цикл: микрофон → имя → распознавание → `handle_command`; диалоговое окно, «да/нет», сон |
| `config.py` | все настройки: голос, модели, пороги, сайты, папки, `NAME_GROUPS` (как называть приложения и их процессы) |
| `phrases.py` | все формулировки команд (регулярки) и `HEARING_FIXES` (ослышки Whisper) |
| `core/parse.py` | быстрый путь без ИИ: `parse_all` → `parse_local`, медиа, поиск, напоминания, громкость приложений |
| `core/commands.py` | `handle_command`: заметки/диктовка → выход/повтор/отмена → `parse_all` → `smart` → Ollama |
| `core/tools.py` | `FUNCTIONS` и `TOOLS` (то, что видит ИИ), `execute_tool` - единственный способ выполнить действие |
| `core/smart.py` | запросы к ИИ без инструментов: вопросы, выделенный текст, умная запись, «что на экране» |
| `core/llm.py` | обёртка над Ollama |
| `core/util.py` | лог, сборка ответа (`compose`, `compose_quiet`), обращение, числа прописью, скомпилированные `R[...]` |
| `core/apps.py` | приложения, браузер, папки, закрытие (процессы, окна папок, вкладки сайтов), окна, яркость, диктовка |
| `core/media.py` | плееры через Windows SMTC, громкость отдельных приложений, автозапуск музыки |
| `core/audio.py` | pycaw: источники звука, приглушение музыки, пока Харви говорит |
| `core/speech.py` | синтез речи, очередь фраз, звуки «готово/ошибка» |
| `core/stt.py` | Whisper, VAD, слово-активатор (openWakeWord), запись фраз, сбор образцов имени |
| `core/daily.py` | время, таймеры, напоминания, заметки, погода, курс, режим сна, питание ПК и подтверждения |
| `core/gcal.py` | Google Календарь и Задачи: планы на день, встречи (цвет, длительность), задачи со сроком; вход - `python -m core.gcal` |
| `core/system.py` | сочетания клавиш и любые клавиши («нажми ctrl g», `press_keys`), диски, загрузка ЦП/ГП, микрофон |
| `core/files.py` | файлы в открытой папке проводника: создать, открыть, выделить, удалить в корзину (после «да»), закрыть окна папок |
| `core/game.py` | игровой режим: игра на весь экран → модель ИИ выгружается сразу после ответа, приоритет Харви ниже |
| `core/steam.py` | игры из библиотеки Steam: список из appmanifest, названия сравниваются в латинице, запуск через steam:// |
| `core/calc.py` | вычисления, единицы, валюты |
| `core/winapi.py`, `core/uia.py` | ctypes: клавиатура, буфер обмена, окна, процессы; UI Automation |
| `core/tray.py` | значок в трее, автозапуск, перезапуск, единственный экземпляр |
| `log_report.py` | отчёт по логу; заново прогоняет фразы из лога через текущие правила (✓ и регрессии) |
| `wake/КАК ОБУЧИТЬ.txt` | как обучить и подключить свою модель имени |

Не попадают в git (см. `.gitignore`) и не должны туда попасть: `harvey.log*`, `crash.log*`, `notes.txt`,
`reminders.json`, `отчёт по логу.txt`, модели (`piper/`, `silero/`, `wake/*.onnx`), образцы `wake/samples/`.
В логах - распознанная речь человека.

## Как добавить формулировку или команду

Основной цикл улучшений такой: открыть отчёт по логу, добавить фразу, написать тест, прогнать тесты, закоммитить.

1. `log_report.py` (или пункт трея «Отчёт: что Харви не поняла») показывает фразы, которые ушли в ИИ.
   Пометка ✓ значит, что текущие правила такую фразу уже понимают. Раздел «Регрессии» появляется, если правка что-то сломала.
2. Новая формулировка существующей команды - это строка в нужном списке `phrases.py`. Ослышка Whisper
   («диспетер», «полный кран») добавляется в `HEARING_FIXES`. Ещё одно имя приложения - в `NAME_GROUPS` в `config.py`.
3. Новое действие:
   - функция в подходящем модуле `core/`;
   - запись в `FUNCTIONS` в `core/tools.py`, а если её должен уметь вызывать ИИ - ещё и описание в `TOOLS`;
   - правило в `core/parse.py`, которое возвращает `lambda: tools.execute_tool("имя", {...})`.
4. Добавь случай в `tests/test_phrases.py` (`PHRASE_CASES`): фраза и ожидаемые вызовы. Неудачи, которые уже
   были, тоже фиксируются тестами.
5. `pytest`, затем коммит.

**Порядок проверок в `parse_local` и `parse_all` важен.** Комментарии в коде объясняют, почему одно правило стоит раньше
другого. Примеры: «сними с паузы» не должно стать паузой, «включи звук» не должно стать медиа, «закрой вкладку» - это
клавиша, а не `close_app`. Регулярка, которая должна покрывать фразу целиком, пишется с `^…$`.

## Соглашения в коде

- **Ответ инструмента - строка с префиксом** (`core/util.py`):
  - без префикса - обычное действие («открыла Telegram»): в тихом режиме звучит только сигнал «готово»;
  - `INFO` (`~`) - это нужно произнести вслух (время, погода);
  - `FAIL` (`!`) - ошибка: сигнал ошибки и короткое объяснение;
  - `RAW` (`=`) - произнести ровно эту фразу (вопрос «Вы уверены?», «Что открыть?»).
- **Род.** Пиши `f"открыл{END}"`, а не «открыла»: `END` зависит от `FEMALE_VOICE`. Обращение «господин» в текстах пишется
  как есть, `util.address()` заменит или уберёт его по настройкам.
- **Импорты явные.** `from config import (...)` и `from phrases import (...)` перечисляют только нужные имена,
  `import *` не используется. Новая настройка добавляется в `config.py`, а затем в список импорта модуля.
- Действия выполняются только через `tools.execute_tool`: он пишет результат в лог и ловит исключения.
  Тесты подменяют именно его, поэтому в `parse.py` нужно вызывать `tools.execute_tool(...)` через модуль.
- Логируй через `log("Тег", текст)`. Теги «Без ИИ», «К ИИ», «Результат», «Ошибка» и «Время» разбирает `log_report.py`.
  Не меняй их, не обновив отчёт.
- Стиль: короткие функции, docstring и комментарии по-русски, объясняющие «почему». Обычно в комментарии есть
  пример фразы из жизни («закрой, браузер и яндекс музыку»).

## Потоки и Windows: что уже ломалось

- **WinRT и SMTC** (плееры) вызываются только через `media._smtc_run(...)`: он использует один поток MTA со своим циклом asyncio.
  Если вызывать `asyncio.run` из главного потока, где comtypes включил STA, каждый вызов даёт `RPC_E_WRONG_THREAD`
  (0x8001010e). Эти ошибки пишутся в `crash.log` как «Windows fatal exception».
- **Трей не обращается к COM** (микрофон, звук): из его потока процесс падал. Трей только выставляет флаг,
  а выполняет главный цикл (см. `system.mic_on_requested`).
- `harvey.py` завершается через `os._exit(0)`: обычный выход при выгрузке CUDA падает с 0xc0000409.
- `crash.log` - вывод faulthandler (стек при падении в C-коде). При запуске файл ротируется, если он больше `LOG_MAX_MB`.
- Яндекс Музыку Windows не видит как плеер, пока в ней ни разу не нажали «играть». Поэтому `_autoplay_when_ready`
  нажимает кнопку через UI Automation.
- Firefox отдаёт Windows один плеер на весь браузер и иногда не принимает паузу. В этом случае нажимается медиа-клавиша,
  но только если звучащий браузер и есть текущий плеер.

## Подводные камни при правке файлов

- **Обратные слеши.** Регулярки в `phrases.py` полны `\b`, `\s`, `\1`. В этой среде Bash-heredoc и `python -c`
  могут превратить `\\b` в символ Backspace (0x08), и фраза молча перестанет работать. Тест
  `test_no_control_chars_in_source` это ловит. Правь такие строки инструментом Edit/Write, а не через shell.
- В файлах смешанные окончания строк (CRLF и LF). Если правишь файл скриптом, сохраняй окончания, которые в нём уже есть.
- Имена в регулярках проверяются по тексту в нижнем регистре, без имени «Харви» и с исправленными ослышками
  (`parse.fix_hearing`).

## Порядок работы

- Проверенные изменения (тесты зелёные) коммить сразу, не спрашивая. Сообщение коммита - по-русски:
  первая строка о том, что изменилось для пользователя, ниже детали.
- Не коммить логи, заметки, модели и образцы голоса.
- Если что-то проверить вживую не удалось (например, пауза в браузере), прямо скажи об этом.
